    Chapter 03. 입력과 출력 — 자판기 시뮬레이터 만들기¶

    Part 1. 출발선 — 수학과 코딩이 만나는 순간 | 3차시 (50분)

    🎯 이 장에서 배우는 것¶

    • 수학 함수의 '입력 → 처리 → 출력' 구조를 일상 사례로 설명할 수 있다
    • 엔트리에서 '묻고 기다리기' 블록으로 사용자 입력을 받을 수 있다
    • 간단한 자판기 프로그램을 완성하여 입출력 흐름을 체험할 수 있다

    📚 핵심 개념¶

    개념 1: 입력 → 처리 → 출력¶

    1. 비유로 시작 🥤

    자판기에 동전(입력) 을 넣으면, 기계가 금액을 확인(처리) 하고, 음료(출력) 가 나옵니다. 이 흐름은 마치 수학 함수와 같아요!

    2. 정확한 정의

    수학에서 함수 f(x) = y 는 "x를 넣으면 규칙 f를 거쳐 y가 나온다"는 뜻입니다. 프로그래밍에서도 똑같습니다.

    • 입력(Input): 프로그램에 전달하는 값 (동전, 키보드 입력 등)
    • 처리(Process): 규칙에 따라 값을 판단하거나 계산하는 과정
    • 출력(Output): 처리 결과를 화면에 보여주는 것
    flowchart LR A["🪙 입력\n동전 1000원"] --> B["⚙️ 처리\n금액 비교"] B --> C["🥤 출력\n콜라 나옴!"]

    3. 예시로 확인

    일상 속 입력-처리-출력을 찾아볼까요?

    • 자판기: 동전 → 금액 확인 → 음료 배출
    • 계산기: 숫자 입력 → 연산 → 결과 표시
    • 엘리베이터: 층 버튼 → 현재 층과 비교 → 이동

    💡 생각해보기: 학교 급식 배식대도 입력-처리-출력 구조일까요? 학생(입력) → 메뉴 확인(처리) → 음식 배분(출력)!

    개념 2: '묻고 기다리기' 블록¶

    1. 비유로 시작 🎤

    '묻고 기다리기' 블록은 마치 자판기 동전 투입구와 같아요. 사용자가 값을 넣을 때까지 기다렸다가, 값이 들어오면 다음 단계로 넘어갑니다.

    2. 정확한 정의

    엔트리의 '묻고 기다리기' 블록은 화면에 질문을 보여주고, 사용자가 키보드로 답을 입력할 때까지 프로그램을 멈춥니다. 입력된 값은 '대답' 이라는 특별한 저장소에 자동으로 담깁니다.

    • '묻고 기다리기': 질문을 던지고, 사용자의 입력을 기다리는 블록
    • '대답': 사용자가 입력한 값이 저장되는 곳 (변수와 비슷)

    3. 예시로 확인

    [묻고 기다리기: "금액을 입력하세요"]  ←  질문 표시
          ↓
사용자가 "1000" 입력
          ↓
[대답] 에 "1000" 저장됨  ←  이 값을 꺼내 쓸 수 있음

    ⚠️ 주의: '대답'에 저장된 값은 글자(문자열) 입니다. 숫자 비교를 하려면 엔트리가 자동으로 변환해주지만, 이 점을 기억해두세요!

    🔨 따라하기: 자판기 시뮬레이터 만들기¶

    Step 1: 프로젝트 시작하기¶

    엔트리(playentry.org)에 접속하여 '작품 만들기' 를 클릭합니다.

    • 기본 오브젝트(엔트리봇)를 자판기 역할로 사용합니다
    • 배경은 자유롭게 설정해도 좋아요

    Step 2: 금액 입력받기¶

    아래 블록을 조립하세요.

    [시작하기 버튼을 클릭했을 때]
[묻고 기다리기: "자판기입니다! 금액을 입력하세요 (500, 1000, 1500)"]

    실행 결과: 화면 아래에 입력창이 나타나고, 사용자가 숫자를 입력할 수 있습니다.

    Step 3: 조건으로 음료 결정하기¶

    입력된 금액에 따라 다른 음료를 출력하는 조건 블록을 추가합니다.

    [만일 (대답) = "500" 이라면]
    [말하기: "🥛 우유가 나왔습니다!"]
[아니면 만일 (대답) = "1000" 이라면]
    [말하기: "🥤 콜라가 나왔습니다!"]
[아니면 만일 (대답) = "1500" 이라면]
    [말하기: "🧃 주스가 나왔습니다!"]
[아니면]
    [말하기: "❌ 해당 금액의 음료가 없습니다."]

    실행 결과: 

    (사용자가 1000 입력 시)
→ "🥤 콜라가 나왔습니다!"

    Step 4: 흐름 확인하기¶

    전체 흐름을 다이어그램으로 정리해봅시다.

    flowchart TD A["▶ 시작 버튼 클릭"] --> B["💬 금액을 입력하세요"] B --> C{"대답 = 500?"} C -- 예 --> D["🥛 우유 출력"] C -- 아니오 --> E{"대답 = 1000?"} E -- 예 --> F["🥤 콜라 출력"] E -- 아니오 --> G{"대답 = 1500?"} G -- 예 --> H["🧃 주스 출력"] G -- 아니오 --> I["❌ 해당 음료 없음"]

    Step 5: 실행하고 테스트하기¶

    ▶ 시작 버튼을 누르고, 아래 값을 차례로 입력해보세요.

    • 500 입력 → 우유가 나오나요? ✅
    • 1000 입력 → 콜라가 나오나요? ✅
    • 2000 입력 → "해당 금액의 음료가 없습니다" 가 나오나요? ✅

    💡 알아보기: 이 자판기의 함수를 수학으로 쓰면 이렇습니다. - f(500) = 우유 - f(1000) = 콜라 - f(1500) = 주스

    ⚠️ 주의할 점¶

    1. '대답'은 새 질문이 나오면 덮어씌워집니다 '묻고 기다리기'를 두 번 사용하면, 두 번째 입력값이 '대답'에 저장됩니다. 이전 값을 기억하려면 변수에 따로 저장해야 합니다. (변수는 다음 차시에서 배워요!)

    2. 숫자와 글자를 혼동하지 마세요 사용자가 "천원"이라고 입력하면 "1000"과 같지 않습니다. 조건 블록에서 비교하는 값과 정확히 같은 형태로 입력해야 합니다.

    ✅ 점검하기¶

    1. (기본) 빈칸을 채워보세요.

    자판기의 작동 원리를 입력-처리-출력으로 나누면: - 입력: ( ① ) - 처리: ( ② ) - 출력: ( ③ )

    정답 확인 ① 동전(금액) 투입 ② 금액이 충분한지 비교·판단 ③ 해당 음료 배출

    2. (응용) 다음 중 '입력 → 처리 → 출력' 구조가 아닌 것은?

    • A. 비밀번호 입력 → 확인 → 잠금 해제
    • B. 햇빛 → 식물 광합성 → 산소 배출
    • C. 책을 펼침 → 책이 펼쳐져 있음
    정답 확인 **C.** 책을 펼치는 행위는 '처리(규칙에 따른 판단이나 계산)' 과정이 없으므로, 함수적 입출력 구조라 보기 어렵습니다. A와 B는 모두 입력값을 규칙에 따라 처리하여 결과를 내보내는 구조입니다.

    3. (심화·도전) 자판기 메뉴를 5개로 늘려보세요!

    기존 3개 메뉴(우유, 콜라, 주스)에 2개 메뉴를 추가하여 자판기를 확장해보세요.

    • 예: 800원 → 사이다, 2000원 → 스무디
    힌트 확인 '아니면 만일' 블록을 2개 더 추가하면 됩니다. 기존 코드에서 `[아니면]` 바로 위에 새로운 `[아니면 만일 (대답) = "800" 이라면]` 블록을 끼워 넣어보세요!
